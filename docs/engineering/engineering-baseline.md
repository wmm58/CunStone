# CunStone v0.1 工程基线

- 日期：2026-11-02
- 状态：已确认
- 适用范围：CunStone v0.1 的页面与功能开发

本文只记录已确认的工程技术口径；产品行为仍以蓝图和对应 OpenSpec Change 为准。

## 1. 技术栈

v0.1 使用以下前端技术栈：

- **构建与开发服务器**：Vite
- **界面框架**：React
- **开发语言**：TypeScript
- **样式方案**：Tailwind CSS

配套工程选择尚未在本基线中确定，包括包管理器、路由方案、状态管理方案、测试框架和浏览器兼容范围。

## 2. 数据保存

v0.1 使用浏览器 **localStorage** 作为应用数据持久化方式。

### 2.1 保存范围

- 用户账号与本地测试登录状态。
- 作品名称、作品状态、创建时间和最后保存时间。
- 后续 Change 产生的作品编辑状态和导出所需配置。

### 2.2 存储边界

- 数据只保存在当前浏览器和当前域名下。
- 刷新页面或重新打开同一浏览器后，数据应恢复。
- 不支持跨浏览器、跨设备或跨浏览器配置同步。
- 清除浏览器站点数据、使用无痕模式或更换设备会导致数据不可用。
- 不将真实短信凭据、支付信息、身份证明或其他敏感密钥写入 localStorage。
- localStorage 中的数据不是安全边界，不能作为生产级身份认证或权限控制依据。

### 2.3 实现约束

- 应用数据应通过统一的本地存储适配层读写，避免业务页面直接散落 localStorage 调用。
- 本地数据必须有命名空间和结构版本，便于后续 Change 扩展字段或迁移数据。
- 读取到损坏或不兼容的数据时，应给出可恢复提示，而不是让页面直接崩溃。
- 当前固定测试验证码只用于本地演示和测试，不代表真实账号安全能力。

## 3. 对现有 Change 1 的影响

当前 `openspec/changes/v0-1-1-change1` 的 `design.md` 和 `tasks.md` 仍包含“服务端权威会话”和“服务端持久化”口径，与本次确认的 localStorage 工程基线冲突。

在开始实现 Change 1 前，需要将相关 Change 产物同步为：

- 使用本地会话/本地测试登录状态，而不是服务端会话。
- 使用 localStorage 保存用户和作品数据，而不是服务端数据库。
- 将“作品归属隔离”定义为本地数据模型中的归属区分，而不是安全隔离。
- 将恢复和自动保存验收限定在同一浏览器、同一站点配置内。

本轮只记录工程基线，不修改该 Change。

## 4. 尚未确认的工程项

- 包管理器选择：npm、pnpm 或其他。
- 路由方案与页面路径组织。
- 状态管理方式。
- 测试框架和端到端测试工具。
- PDF 生成库及中文/尺寸标注支持方式。
- localStorage 的完整数据结构、版本迁移策略和容量上限处理。
- 浏览器最低支持范围。
- 用户清理本地数据、导出备份或恢复数据的交互方式。

## 5. 基线验收

- 项目使用 Vite + React + TypeScript + Tailwind CSS 运行。
- 在同一浏览器和站点下，刷新或重新打开后可以恢复本地保存的作品。
- 清除站点数据后，本地作品和登录状态随之消失。
- 应用不依赖服务端数据库或云同步即可完成 v0.1 的本地数据闭环。
- 不将 localStorage 当作生产级认证、授权或敏感数据存储方案。
