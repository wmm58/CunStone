# editor-binary-editing Specification

## Purpose
让用户在 P2 的自动黑白基础稿上完成手工修整，并通过阴阳刻、左右镜像和系统边框得到可保存、可恢复的纯黑白篆刻稿。

## Requirements

### Requirement: P2 黑白稿编辑入口

P2 必须（MUST）始终允许在“图片编辑”和“黑白稿编辑”之间双向切换，不以是否存在黑白基础稿作为切换条件。没有基础稿时仍显示工具区和空画布说明，但依赖基础稿的画笔、橡皮、撤销重做和预览操作禁用；基础稿只来自当前作品的上传图片。

#### Scenario: 有基础稿时进入编辑

- **WHEN** 用户已上传图片且系统生成了黑白基础稿
- **THEN** 用户可以进入“黑白稿编辑”模式并使用可用工具

#### Scenario: 无基础稿时禁用编辑

- **WHEN** 用户尚未提供图片
- **THEN** 用户可以进入“黑白稿编辑”查看空画布和工具说明，但画笔、橡皮等编辑操作保持禁用

#### Scenario: 任意时刻返回图片编辑

- **WHEN** 用户处于黑白稿编辑模式，无论是否已有基础稿或手动修整
- **THEN** 用户都可以立即切回图片编辑，状态不被重置

### Requirement: 黑色画笔与橡皮

P2 必须（MUST）提供黑色画笔和橡皮；画笔把经过位置的最终可见像素改为黑色，橡皮把经过位置的最终可见像素改为白色。

#### Scenario: 使用画笔补黑

- **WHEN** 用户选择画笔并在黑白稿画布上拖动
- **THEN** 经过的像素变为纯黑，其他像素保持原值

#### Scenario: 使用橡皮去白

- **WHEN** 用户选择橡皮并在黑白稿画布上拖动
- **THEN** 经过的像素变为纯白，其他像素保持原值

#### Scenario: 鼠标与触控笔

- **WHEN** 用户使用鼠标或触控笔在黑白稿画布上连续移动
- **THEN** 系统按连续笔画处理，不只记录离散点击点

### Requirement: 画笔线宽

P2 必须（MUST）提供可调整的画笔线宽，并让同一笔画在不同线宽下产生不同粗细；线宽设置必须随作品保存和恢复。

#### Scenario: 调整线宽

- **WHEN** 用户增大或减小线宽后绘制
- **THEN** 新笔画的粗细随设置变化，已有笔画不被改写

#### Scenario: 恢复线宽

- **WHEN** 用户保存作品并在同一浏览器重新打开
- **THEN** 线宽恢复为最后保存的设置

### Requirement: 撤销与重做

P2 必须（MUST）支持撤销和重做手动编辑；撤销恢复上一笔之前的状态，重做恢复被撤销的笔画，新建笔画后必须清空重做历史。

#### Scenario: 撤销与重做笔画

- **WHEN** 用户完成一笔后点击撤销，再点击重做
- **THEN** 画布先恢复到该笔之前，再恢复该笔画结果

#### Scenario: 新笔画清空重做

- **WHEN** 用户撤销后绘制新笔画
- **THEN** 原重做历史被清空，重做按钮不可用

#### Scenario: 重新打开后的历史

- **WHEN** 用户重新打开已保存作品
- **THEN** 手动编辑结果恢复，但撤销和重做历史从空状态开始

### Requirement: 黑白稿局部放大

P2 必须（MUST）提供非破坏性的画布放大查看能力，允许用户检查局部细节；缩放只改变查看比例，不得改变保存的黑白像素。

#### Scenario: 放大查看

- **WHEN** 用户提高画布缩放比例
- **THEN** 画布显示变大且可通过滚动查看不同区域

#### Scenario: 缩放不影响输出

- **WHEN** 用户在不同缩放比例下保存作品
- **THEN** 保存的黑白稿像素与缩放前一致

### Requirement: 阳刻与阴刻

P2 必须（MUST）提供阳刻和阴刻切换；阴刻必须交换最终黑白稿中的黑色与白色，切换结果必须仍只包含纯黑和纯白像素。

#### Scenario: 切换阴刻

- **WHEN** 用户从阳刻切换到阴刻
- **THEN** 黑白稿的黑色与白色反转，手动修整和边框随当前模式重新渲染

#### Scenario: 切回阳刻

- **WHEN** 用户从阴刻切回阳刻
- **THEN** 黑白稿恢复到与切换阴刻前一致的阳刻结果

### Requirement: 正常方向与左右镜像

P2 必须（MUST）提供正常方向和左右镜像切换；镜像只水平翻转最终画面，不改变印章实际宽高，并保存最后选择的方向。

#### Scenario: 开启左右镜像

- **WHEN** 用户选择左右镜像
- **THEN** 最终黑白画面沿水平方向翻转，再次切换可恢复原方向

#### Scenario: 恢复镜像方向

- **WHEN** 用户保存镜像作品并重新打开
- **THEN** 作品恢复为最后保存的镜像方向和对应画面

### Requirement: 纯黑白输出约束

完成手动编辑、阴阳刻、镜像和边框后，可保存的黑白稿必须（MUST）只包含不透明纯黑和纯白像素，不得出现灰色或半透明像素。

#### Scenario: 组合操作后的像素检查

- **WHEN** 用户依次执行画笔、橡皮、阴刻、镜像并选择边框
- **THEN** 最终画布中的每个像素只能是 `#000000` 或 `#FFFFFF`

### Requirement: 处理参数变化与手动修整冲突

当作品已有手动修整时，修改图片源、外形、尺寸、任一有效背景颜色规则的颜色或容差、剪影/轮廓效果或轮廓粗细，并且该修改会重新生成基础稿时，系统必须（MUST）在清除修整前提示用户确认；用户取消时必须保留原参数和手动修整。

#### Scenario: 确认重置修整

- **WHEN** 已有手动修整的用户修改 01–04 中会重新生成基础稿的参数并确认提示
- **THEN** 系统应用新参数、重新生成基础稿并清空手动修整与撤销重做历史

#### Scenario: 取消重置修整

- **WHEN** 已有手动修整的用户修改 01–04 处理参数后取消提示
- **THEN** 原处理参数、手动修整和撤销重做历史保持不变

#### Scenario: 变更多背景规则

- **WHEN** 已有手动修整的用户新增并取样背景颜色、重新取样、删除规则或调整任一有效规则容差
- **THEN** 系统按同一重置确认规则处理，不静默丢弃手动修整

#### Scenario: 变更轮廓粗细

- **WHEN** 已有手动修整的用户调整轮廓线稿粗细
- **THEN** 系统先请求重置确认，确认后重新生成基础稿并清空手动修整

#### Scenario: 没有手动修整

- **WHEN** 用户尚未产生手动修整并修改 01–04 处理参数
- **THEN** 系统直接重新生成基础稿，不显示重置提示

### Requirement: 保存与恢复黑白编辑状态

作品必须（MUST）保存手动修整覆盖层、画笔大小、橡皮大小、阴阳刻、镜像、边框样式、边框粗细和毫米边框外边距；在同一浏览器重新打开时必须恢复最后保存的编辑结果。

#### Scenario: 保存并重新打开

- **WHEN** 用户完成画笔、橡皮、阴刻、镜像和边框粗细设置并保存作品
- **THEN** 重新打开后恢复相同的手动像素、画笔/橡皮大小、阴阳刻、镜像、边框样式、边框粗细和边框外边距

#### Scenario: 自动保存笔画

- **WHEN** 用户完成一笔手动编辑并停止操作超过自动保存延迟
- **THEN** 最新修整结果写入 localStorage，保存状态显示成功

### Requirement: 黑白编辑保存失败处理

当黑白编辑状态无法写入 localStorage 时，系统必须（MUST）保留当前内存画布、显示保存失败提示，并允许用户重试。

#### Scenario: 容量不足

- **WHEN** 保存手动修整时触发容量不足或写入异常
- **THEN** 当前画布和工具设置不丢失，界面显示失败状态，下一次显式保存可以重试

### Requirement: Change 3 页面边界

Change 3 必须（MUST）只扩展 P2 的黑白稿编辑和印章控制；“A4 导出”按钮可以展示但不得进入未实现的 P4，P3 作品列表、红印预览和 PDF 导出留待后续 Change。

#### Scenario: A4 占位按钮

- **WHEN** 用户点击 P2 的“A4 导出”占位按钮
- **THEN** 系统不跳转到 P4、不生成 PDF，并说明该能力将在后续 Change 提供

#### Scenario: 不暴露后续页面

- **WHEN** 用户查看 Change 3 完成后的 P2
- **THEN** 页面不出现 P3 作品列表、预览弹窗、A4 排版或 PDF 下载功能

### Requirement: 不使用自建 API 或外部 AI

Change 3 的笔画处理、撤销重做、缩放、阴阳刻、镜像、边框和保存必须（MUST）在当前浏览器本地完成，不得发起业务 API 请求或调用外部 AI。

#### Scenario: 本地完成编辑

- **WHEN** 用户完成 Change 3 的全部黑白编辑流程
- **THEN** 系统不调用自建 API、服务端、外部 AI 服务或 API Key

### Requirement: Change 3 基础验收流程

系统必须（MUST）支持从当前黑白基础稿开始，完成手动修整、印章控制、边框粗细调整、保存和同浏览器恢复的完整流程。

#### Scenario: 完整恢复流程

- **WHEN** 用户使用固定样本进入黑白稿编辑，执行画笔、橡皮、撤销、重做、调整线宽、选择阴刻、左右镜像、选择边框并调整边框粗细后保存
- **THEN** 同一浏览器重新打开作品时恢复相同黑白结果和全部印章设置

#### Scenario: 纯色去底残留修整

- **WHEN** 多颜色去底后的固定样本仍存在残留边缘
- **THEN** 用户可以使用橡皮清除残留，并把修整结果保存和恢复

### Requirement: 手绘模块与独立工具大小

P2 的原黑白稿编辑模块必须（MUST）改名为“手绘”；画笔和橡皮分别保存大小，选择画笔时只显示画笔大小滑杆，选择橡皮时只显示橡皮大小滑杆。

#### Scenario: 手绘画笔

- **WHEN** 用户选择画笔
- **THEN** 手绘区显示画笔大小滑杆和当前 px 数值

#### Scenario: 手绘橡皮

- **WHEN** 用户选择橡皮
- **THEN** 手绘区显示橡皮大小滑杆和当前 px 数值

#### Scenario: 独立保存

- **WHEN** 用户分别设置画笔和橡皮大小并保存
- **THEN** 重新打开作品后两种大小分别恢复

### Requirement: 手绘尺寸光标

用户使用画笔或橡皮在画布操作时，画布必须（MUST）显示与当前工具大小一致的圆形光标，并在界面显示当前工具名称和 px 数值。

#### Scenario: 光标尺寸

- **WHEN** 用户移动画笔或橡皮光标
- **THEN** 圆形光标随当前工具大小变化，界面显示对应名称和 px 数值

### Requirement: 边框粗细跨页面一致

边框粗细必须（MUST）由同一份最终黑白渲染状态驱动，并在 P2 编辑画布、P3 红印与黑白预览、P4 缩略图和 PDF 中保持一致。

#### Scenario: P2 调整后预览

- **WHEN** 用户在 P2 调整边框粗细并保存
- **THEN** P3 的红印效果和黑白印稿使用相同粗细

#### Scenario: PDF 输出边框粗细

- **WHEN** 用户把带边框粗细设置的作品下载为 PDF
- **THEN** PDF 中边框粗细与 P3 黑白预览一致

### Requirement: 新系统边框

P2 必须（MUST）提供无、单线、双线三种新边框，不得提供粗线或残破边；边框适配方形、长方形和圆形印章，并提供 1–8 级边框粗细和 0–20 mm 边框外边距。

#### Scenario: 选择边框

- **WHEN** 用户查看阴/阳刻与边框模块
- **THEN** 只出现无边框、单线和双线，不出现粗线或残破边

#### Scenario: 圆形边框

- **WHEN** 用户为圆形印章选择边框
- **THEN** 边框沿圆形边界显示，不出现在圆形范围外的白色角落

#### Scenario: 调整边框粗细

- **WHEN** 用户拖动边框粗细滑杆
- **THEN** 当前边框线宽按 1–8 级设置实时变化

#### Scenario: 调整边框外边距

- **WHEN** 用户拖动边框外边距滑杆
- **THEN** 边框与画布外边缘之间的距离按 0.1 mm 步进实时变化

#### Scenario: 无边框时禁用控件

- **WHEN** 用户选择“无边框”
- **THEN** 边框粗细和边框外边距控件禁用
