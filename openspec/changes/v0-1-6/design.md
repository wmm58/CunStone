# 设计（Design）

## Context

Change 5 已产生包含毫米位置、旋转、页索引和尺寸标记的 P4 排版。Change 6 需要将该临时布局转换为可下载 PDF，并完成 v0.1 全流程验收。

## Goals / Non-Goals

**目标：**

- 浏览器本地生成多页 A4 PDF。
- 按毫米 1:1 嵌入最终黑白稿，保留旋转和页内位置。
- 加入尺寸文字和裁剪线。
- 触发浏览器文件下载并完成固定样本端到端验收。

**非目标：**

- 不验证打印机缩放、纸张效果、转印或雕刻。
- 不保存 PDF 历史、导出记录或排版持久化。
- 不调用服务端、API 或外部 AI。

## Decisions

### 决策 1：使用 `pdf-lib`

采用纯浏览器可用的 `pdf-lib` 创建文档和嵌入 PNG。它不依赖服务端，支持多页和毫米/点换算。备选 `jsPDF` 也可行，但本项目采用 `pdf-lib` 便于结构化测试。

### 决策 2：先从作品重建最终黑白图

导出时复用 `renderWorkBlackWhite` 生成最终像素，再写入临时 Canvas 并转为 PNG。红印映射不参与 PDF。

### 决策 3：旋转在图片层完成

对 90° 或 270° 作品，先旋转 Canvas；PDF 绘制时使用交换后的宽高，并围绕原作品中心定位。这样可以保持比例且不依赖复杂 PDF 变换。

### 决策 4：PDF 坐标换算

A4 使用 `595.28×841.89 pt`。毫米转点比例为 `72/25.4`，Y 轴从顶部布局转换为 PDF 底部坐标。

### 决策 5：尺寸和裁剪线

每件作品四角绘制 3 mm 裁剪线，尺寸文字使用 ASCII 兼容格式，如 `25 x 25 mm` 或 `Dia 30 mm`。文字和线条使用纯黑。

### 决策 6：下载使用 Blob URL

PDF 字节转为 `application/pdf` Blob，通过临时 `<a download>` 触发下载，随后撤销 Blob URL。不保存文件到应用数据。

### 决策 7：失败处理

无作品时提示先添加；生成失败显示错误，不抛出未捕获异常。生成中禁用按钮并显示状态。

### 决策 8：全流程验收

固定样本使用真实 Chrome 完成登录、编辑、保存、P3 预览、P4 排版和 PDF 下载；使用 PDF 解析库验证 A4 页数、页面尺寸和文件可打开。

## Risks / Trade-offs

- PDF 文件可能较大 → 仅在下载时生成，不持久化。
- 旋转图片可能导致布局边界变化 → 用中心点定位并在 P4 中沿用相同旋转。
- 字体只适合 ASCII 尺寸文字 → 使用 `x` 和 `Dia`，避免中文编码问题。
- 浏览器下载策略不同 → 使用标准 Blob 下载并在真实 Chrome 中验收。

## Migration Plan

新增 `pdf-lib` 依赖和导出模块；不修改持久作品结构。回滚恢复 P4 占位按钮即可。

## Test Strategy

- PDF 单元测试：A4 尺寸、多页、毫米换算、尺寸文字和裁剪线路径。
- P4 组件测试：无作品、成功下载、失败提示、生成中状态。
- 集成测试：P3 → P4 → 下载并验证 PDF 页数与尺寸。
- 真实 Chrome：保存 PDF 文件并用 `pdf-lib` 重新加载验证。
- 最终门禁：测试、类型检查、构建、OpenSpec 严格校验和生产源码扫描。
