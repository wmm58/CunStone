# 设计（Design）

## 背景

这是 CunStone v0.1 六个规划变更中的第一个。线框图将 P1 定义为手机号入口页面，将 P2 定义为创作编辑页外壳。后续变更会加入图片处理、作品列表、A4 排版和 PDF 导出，因此本次变更必须建立干净的基础，不能提前接管这些能力。

工程基线已确认使用 Vite + React + TypeScript + Tailwind CSS，并使用 localStorage 保存应用数据。因此 v0.1 定位为单浏览器本地原型，不引入服务端账号、数据库或云同步。

## 目标 / 非目标

**目标：**

- 提供可用的 P1 本地测试登录/注册流程，使用固定测试验证码。
- 登录成功后将用户直接带入 P2 编辑页外壳。
- 建立以 localStorage 为唯一持久化来源的本地账号与作品基础。
- 支持本地账号之间的作品数据显示隔离。
- 支持作品命名、草稿/已完成状态、草稿保存、已完成保存和重新打开。
- 建立作品元数据的本地自动保存行为，并显示最后保存状态。

**非目标：**

- 真实短信发送、身份核验或缴费。
- 服务端账号、服务端会话、数据库、跨设备同步或生产级安全隔离。
- 图片上传、手绘、纯色去底、黑白转换或编辑工具。
- P3 作品列表筛选、预览、全选或删除。
- P4 作品选择、A4 排版或 PDF 导出。
- 分享、社区、手机 App 或桌面封装。

## 决策

### 决策 1：v0.1 采用纯前端本地原型

使用 Vite + React + TypeScript + Tailwind CSS 构建前端，所有业务状态通过 localStorage 持久化。v0.1 不引入服务端数据库或服务端会话。

考虑过的替代方案：先建设服务端认证和数据库。该方案安全性和扩展性更好，但与当前工程基线及单浏览器原型目标不一致，因此本阶段不采用。

### 决策 2：固定测试验证码在客户端校验

P1 使用配置在应用中的固定测试验证码完成本地测试身份进入。该验证码只用于演示，不构成真实认证或安全能力。

考虑过的替代方案：接入真实短信服务。真实短信、身份核验和缴费已延期，因此不采用。

### 决策 3：手机号作为本地账号标识

系统规范化用户输入的手机号，并将规范化后的手机号作为本地账号的唯一标识。首次成功登录时创建本地账号，后续登录复用同一本地账号，并设置当前活动本地账号。

考虑过的替代方案：拆分独立注册和登录路由。线框图只提供一个合并的登录/注册入口，v0.1 暂不需要独立账号流程，因此不拆分。

### 决策 4：统一通过 localStorage 适配层持久化

所有应用数据通过统一的本地存储适配层读写，使用命名空间和结构版本。用户、作品和当前活动本地账号都保存在 localStorage 中。

考虑过的替代方案：页面直接调用 localStorage。该方式会让数据结构散落且难以迁移，因此不采用。

### 决策 5：持久化两个初始实体

基础能力持久化以下对象：

- 本地用户：标识、规范化手机号、创建时间。
- 本地作品：标识、所属本地账号标识、作品名称、状态、创建时间、最后保存时间。

作品记录故意保留扩展空间，因为后续变更会增加原图、外形、尺寸、黑白编辑状态、镜像方向和边框设置。

### 决策 6：本地账号归属是数据隔离，不是安全边界

作品按所属本地账号标识存储和显示。切换本地账号时只展示当前账号的作品，但不得宣称 localStorage 能阻止用户通过浏览器工具读取或修改数据。

考虑过的替代方案：将本地账号隔离描述为安全权限。该描述不真实，因此不采用。

### 决策 7：作品生命周期从草稿开始

新作品默认进入草稿状态。已命名作品可以保存为草稿，也可以保存为已完成；保存任一状态都会由客户端生成并更新最后保存时间。作品再次保存时，已完成状态必须保留。

完整编辑器后续会复用这套生命周期；Change 1 只需要 P2 外壳中的状态控件和持久化行为。

### 决策 8：自动保存元数据，同时保留显式保存操作

P2 外壳会在作品元数据变化稳定后自动写入 localStorage，同时提供明确的“草稿”和“保存（已完成）”操作。只有本地写入成功后，保存状态提示和最后保存时间才更新；写入失败时，界面需要显示未保存/错误状态，并允许之后重试。

考虑过的替代方案：只提供显式保存。蓝图要求建立自动保存基础，且后续变更依赖可恢复的编辑状态，因此不采用。

### 决策 9：P1 和 P2 保持最小范围

P1 只包含手机号输入、固定验证码输入和登录/注册操作。P2 只包含作品名称、状态/保存控件、自动保存状态，以及未来编辑工具的外壳。本次变更不实现任何图片处理控件。

由于 P3 在后续变更中实现，Change 1 提供一个最小化的、按作品标识打开的 P2 路由，用于从 localStorage 重新打开已保存作品。完整的作品列表导航不在本次范围内。

## 风险 / 权衡

- 固定测试验证码不具备安全性 → 明确标记为本地演示能力，正式上线前必须替换。
- localStorage 可被用户直接读取和修改 → 不把它当作安全边界，不保存敏感数据。
- 清除站点数据或更换浏览器会导致数据丢失 → 在界面和文档中明确本地存储限制；后续提供导出或服务端同步。
- localStorage 容量有限 → Change 1 只保存轻量元数据；后续图片数据如超出容量，应评估 IndexedDB 或压缩策略。
- 多标签页同时保存可能相互覆盖 → 以最后一次成功写入为准，并在后续需要时增加版本或冲突提示。

## 迁移方案

这是全新的本地数据基础，没有既有应用数据需要迁移。首次运行时创建带命名空间和版本号的 localStorage 数据结构；后续字段扩展时按版本进行迁移。未来如果需要真实公开多用户、跨设备同步或安全隔离，应引入服务端账号与持久化，并通过存储适配层迁移本地数据。

## 待确认事项

- 包管理器、路由方案、状态管理、测试框架和浏览器支持范围仍可在实施阶段选择，但不得改变本设计定义的 localStorage 与单浏览器边界。
