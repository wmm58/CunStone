# Spec Delta

## Purpose

为单浏览器版本的 CunStone v0.1 提供本地测试登录入口、按本地账号区分作品的 localStorage 基础，以及可持久化的草稿生命周期。

## ADDED Requirements

### Requirement: 本地固定测试码登录与注册

P1 登录/注册页必须使用手机号和固定测试验证码完成本地测试登录；手机号尚未创建本地账号时，系统必须创建账号（MUST）。

#### Scenario: 首次手机号注册

- **WHEN** 未注册用户在 P1 输入有效手机号和配置好的固定测试验证码
- **THEN** 系统在 localStorage 中创建本地用户账号并完成登录

#### Scenario: 已有手机号登录

- **WHEN** 已注册用户在 P1 输入同一手机号和配置好的固定测试验证码
- **THEN** 系统复用已有本地账号，且不重复创建账号

#### Scenario: 验证码错误

- **WHEN** 用户输入有效手机号和错误的验证码
- **THEN** 系统拒绝登录，且不创建账号、不设置活动本地账号

### Requirement: v0.1 不发送真实短信

v0.1 本地测试登录流程必须使用配置好的固定测试验证码，且不得发送真实短信（MUST）。

#### Scenario: 固定验证码登录不发送短信

- **WHEN** 用户在 v0.1 的 P1 请求验证码
- **THEN** 系统使用固定测试验证码路径，不调用外部短信服务

### Requirement: 无活动本地账号时阻止访问

系统必须要求存在本地活动账号状态，才能访问 P2 或任何已保存作品（MUST）。

#### Scenario: 无本地账号直接访问

- **WHEN** 没有活动本地账号的访客请求 P2 编辑页外壳或作品数据
- **THEN** 系统将其带回 P1，且不展示任何本地作品数据

### Requirement: 登录后进入 P2

本地注册或登录成功后，系统必须将用户带入 P2 创作编辑页外壳（MUST）。

#### Scenario: 登录成功后的目标页面

- **WHEN** 用户在 P1 完成本地测试登录
- **THEN** 用户进入 P2 创作编辑页外壳，而不是作品列表页

### Requirement: 作品按本地账号区分

每个作品必须且只能归属于一个本地账号；切换本地账号后，系统不得在界面中展示其他账号的作品（MUST）。

#### Scenario: 切换本地账号

- **WHEN** 用户从一个本地账号切换到另一个本地账号
- **THEN** 界面只展示新账号自己的作品，不展示前一个账号的作品

#### Scenario: localStorage 不是安全边界

- **WHEN** 用户通过浏览器工具查看 localStorage
- **THEN** 系统不保证数据对用户隐藏，也不将其视为生产级权限隔离

### Requirement: 用户可以创建并命名作品

存在活动本地账号的用户必须能够在 P2 创建新作品，填写可编辑的名称，并默认使用草稿状态（MUST）。

#### Scenario: 创建新作品

- **WHEN** 有活动本地账号的用户新建作品并输入有效名称
- **THEN** 系统在 localStorage 中创建归属于当前本地账号的草稿作品，并保存该名称

### Requirement: 保存草稿写入本地作品元数据

用户将作品保存为草稿时，系统必须把作品名称、状态和最后保存时间写入 localStorage（MUST）。

#### Scenario: 保存并更新最后保存时间

- **WHEN** 用户将一个已命名作品保存为草稿
- **THEN** 作品名称被保存，状态为草稿，客户端生成并更新最后保存时间

### Requirement: 用户可以将作品保存为已完成

系统必须允许当前本地账号将一个已命名作品保存为已完成状态（MUST）。

#### Scenario: 标记作品为已完成

- **WHEN** 作品所属用户使用“保存（已完成）”操作保存已命名作品
- **THEN** 作品状态变为已完成，客户端生成并更新最后保存时间

### Requirement: 已保存作品可以恢复

系统必须允许同一浏览器中的本地账号重新打开自己保存过的作品，并恢复最后保存的名称和状态（MUST）。

#### Scenario: 重新打开已保存草稿

- **WHEN** 用户在同一浏览器中完成本地登录并打开之前保存的草稿
- **THEN** P2 显示该作品最后保存的名称和草稿状态

### Requirement: 自动保存基础能力保留编辑

系统必须在不要求导出的情况下把符合条件的作品元数据变更写入 localStorage，并展示最后保存状态（MUST）。

#### Scenario: 自动保存的元数据在离开后保留

- **WHEN** 用户修改作品名称或状态，并在本地自动保存完成后离开当前页面
- **THEN** 再次打开作品时恢复到已保存的值和最后保存时间

### Requirement: 作品状态支持草稿和已完成

作品生命周期状态必须为草稿或已完成；新建作品必须从草稿状态开始（MUST）。

#### Scenario: 草稿保持草稿状态

- **WHEN** 用户将已有作品保存为草稿
- **THEN** 已保存状态仍为草稿

#### Scenario: 已完成状态被保留

- **WHEN** 一个已标记为完成的作品再次保存
- **THEN** 已保存状态仍为已完成

### Requirement: 数据仅限当前浏览器和站点

v0.1 必须只依赖当前浏览器和当前站点的 localStorage，不提供跨浏览器、跨设备或云同步（MUST）。

#### Scenario: 同一浏览器刷新后恢复

- **WHEN** 用户在同一浏览器中刷新或重新打开站点
- **THEN** 系统从 localStorage 恢复本地账号和作品数据

#### Scenario: 清除站点数据

- **WHEN** 用户清除当前站点的浏览器数据
- **THEN** 系统无法恢复已删除的本地账号和作品

### Requirement: Change 1 基础验收流程

系统必须支持 Change 1 的端到端流程：从 P1 本地登录开始，创建草稿，并在同一浏览器中恢复作品（MUST）。

#### Scenario: 完成基础流程

- **WHEN** 新用户使用固定测试验证码登录，创建并命名作品，保存为草稿，离开后在同一浏览器再次登录
- **THEN** 同一本地账号能够重新打开该作品，并看到已保存的名称、草稿状态和最后保存时间
