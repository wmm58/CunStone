# 设计（Design）

## Context

Change 1 已提供本地账号、作品生命周期、手动保存和自动保存基础。Change 2 已归档，P2 可以上传图片或手绘、去除纯色背景、生成适配印章外形的纯黑白基础稿，并通过 localStorage v2 保存源图和 01–04 参数。

当前限制：

- 黑白稿由源图和参数即时计算，没有可编辑层。
- `EditorCanvas` 的黑白稿模式只读。
- `WorkRecord` 只有 `imageState`，没有手动修整、阴阳刻、镜像或边框状态。
- `ImagePreparationPanel` 已承担 01–04、画布和输入逻辑，继续叠加 05–06 会形成过大组件。
- P3/P4 尚未实现，不能在本 Change 提前接管作品列表、预览、排版或 PDF。

本设计依据 `proposal.md` 和 `specs/editor-binary-editing/spec.md`。

## Goals / Non-Goals

**目标：**

- 在 Change 2 黑白基础稿上增加可持久化的手动修整覆盖层。
- 提供画笔、橡皮、撤销、重做、局部放大和线宽设置。
- 提供阴阳刻、左右镜像和五种系统边框。
- 将本地数据从 v2 平滑升级到 v3，迁移 v1/v2 数据。
- 保持自动保存、显式保存、容量失败提示和同浏览器恢复行为。
- 在新增功能前拆分编辑组件，避免继续扩大单一页面组件。

**非目标：**

- 不实现 P3 作品列表、卡片、筛选、预览弹窗或删除。
- 不实现 P4 A4 排版、作品多选、拖拽旋转、间距、分页或 PDF。
- 不实现红印预览、自动可刻性检查、复杂抠图、透视校正或真实打印/雕刻验证。
- 不实现服务端 API、数据库、外部 AI、跨设备同步或生产级安全认证。
- 不实现移动端专用编辑交互。

## Decisions

### 决策 1：手动修整使用独立的中性覆盖层

Change 2 生成的纯黑白基础稿保持为只读的“中性层”。手动修整保存为第三层，每个像素只有三种值：

- `0`：不覆盖基础稿。
- `1`：强制为黑色。
- `2`：强制为白色。

选择“强制黑/白”而不是直接修改基础稿，原因是：

- 基础稿仍可由源图和 01–04 参数重建。
- 可以区分“笔刷画黑”和“橡皮擦白”，不需要反推出原始像素。
- 后续渲染阴阳刻、镜像和边框时可以保持确定性。

### 决策 2：渲染顺序固定为“基础稿 → 覆盖层 → 边框 → 阴刻 → 镜像”

最终显示和保存按以下顺序生成：

1. 由 Change 2 管线生成中性黑白基础稿。
2. 应用手动修整覆盖层。
3. 按当前边框选择绘制中性黑色边框。
4. 阴刻时反转全部黑白像素。
5. 左右镜像时水平翻转。
6. 执行纯黑白守卫，输出只含 `#000000`、`#FFFFFF` 且 alpha 为 255 的像素。

边框放在阴刻之前，因此边框与画面使用同一黑白语义；镜像放在最后，保证最终方向与用户保存结果一致。

### 决策 3：阴刻和镜像下仍编辑“最终可见结果”

用户始终看到当前阴刻和镜像后的画面，画笔和橡皮也按最终可见颜色操作。事件坐标和颜色在写入覆盖层前做逆变换：

- 镜像开启时，将屏幕 `x` 映射为画布宽度减一后的反向坐标。
- 阴刻开启时，用户画黑写入“强制白”，用户擦白写入“强制黑”。

这样切换阴刻或镜像不会丢失已有手动修整，撤销历史也不需要因切换模式而清空。

### 决策 4：覆盖层采用 2 bit/像素压缩并校验生成签名

内存中的覆盖层使用每像素一字节的 `0/1/2` 数组，便于高频笔画处理。写入 localStorage 前压缩为 2 bit/像素：

- 最大画布为 512×512，原始覆盖层 262,144 字节。
- 压缩后最多 65,536 字节，Base64 后约 87 KB。
- 保存字段包括压缩数据、宽度、高度和基础稿生成签名。

生成签名是源图 Data URL、外形、宽高、背景色、容差、剪影/轮廓效果和处理算法版本的确定性哈希。重新打开时若签名不匹配，系统不应用旧覆盖层，显示“基础稿已变化，请重新修整”的提示，避免把旧笔画应用到错误画面。

考虑过直接保存最终 PNG：实现简单但体积不可预测，也无法区分基础稿与手动修改。当前方案容量更可控。

### 决策 5：撤销/重做历史只保留在当前会话

每次笔画开始前保存一份压缩覆盖层快照，笔画结束后把快照推入撤销栈。撤销栈最多保留 20 个快照，重做栈最多 20 个；产生新笔画时清空重做栈。

撤销/重做历史不写入 localStorage。重新打开作品只恢复最终覆盖层和工具设置，历史从空状态开始。这样既满足本次编辑的撤销需求，也避免历史占用大量本地容量。

### 决策 6：笔画使用连续栅格化，不在 pointermove 时逐段落盘

画布使用 Pointer Events，支持鼠标和触控笔。相邻采样点之间使用按线宽扩张的线段栅格化，保证快速移动时仍形成连续笔画。

拖动过程中只更新内存覆盖层和画布；`pointerup` 或取消时提交一次状态给 `EditorPage` 触发延迟自动保存。这样避免每个指针移动都写 localStorage。

### 决策 7：线宽和当前工具

线宽以工作画布像素为单位，范围 1–32 px，默认 6 px，步长 1 px。线宽属于作品保存状态。

当前工具（画笔/橡皮）属于临时交互状态，不单独持久化；重新打开作品默认选择画笔但恢复最后保存的线宽。

### 决策 8：局部放大只改变视图

画布缩放范围为 50%–400%，以 25% 为步长，可点击放大/缩小和恢复适应视图。画布放在可滚动容器内，放大后通过滚动查看局部。

缩放比例只存在组件内存，不写入作品，也不参与像素计算或保存比较。

### 决策 9：五种边框使用确定性几何

边框在内边距区域绘制，适配矩形和圆形：

- 无：不添加边框。
- 单线：约 4% 内边距处绘制一条细线。
- 粗线：约 4% 内边距处绘制明显更粗的线。
- 双线：绘制两条分离的线。
- 残破边：以单线为基础，按固定种子和分段规则产生稳定缺口。

边框像素在阴刻前绘制。残破边不得使用每次渲染变化的随机数；缺口根据画布宽高、外形和边框类型计算固定结果。

### 决策 10：01–04 参数变化必须保护手动修整

已有手动修整时，任何 01–04 变化都视为会让基础稿失效：

- 上传或手绘替代源图。
- 改变外形或实际宽高。
- 改变背景色或容差。
- 改变实心剪影/轮廓线稿。

系统先显示确认提示，说明继续会清除手动修整与撤销/重做历史。确认后应用参数、重建基础稿并清空覆盖层；取消则保持原状态。没有覆盖层时不显示提示。

阴阳刻、镜像、边框和线宽不进入基础稿签名，因此切换这些设置不清除手动修整。

### 决策 11：数据升级到 localStorage v3

`WorkRecord` 增加 `binaryState`：

- `overlayData`：压缩覆盖层 Base64 或 `null`。
- `overlayWidth`、`overlayHeight`：覆盖层尺寸或 `null`。
- `generationSignature`：覆盖层对应的基础稿签名或 `null`。
- `brushSize`：1–32 px。
- `carvingMode`：`yang` 或 `yin`。
- `orientation`：`normal` 或 `mirror`。
- `borderStyle`：`none`、`single`、`thick`、`double`、`broken`。
- `editVersion`：当前为 `1`。

本地存储版本从 v2 升级到 v3：

- v1 作品先补 Change 2 默认 `imageState`，再补默认 `binaryState`。
- v2 作品保留全部 `imageState`，补默认 `binaryState`。
- 未知高版本继续安全回退，不覆盖原数据。

### 决策 12：编辑组件先拆分再接入 P2

为避免 `ImagePreparationPanel` 继续膨胀：

- `ImagePreparationPanel` 保留 01–04 控件。
- 新增 `BinaryEditorPanel` 承载 05 与 06 控件。
- 新增 `BinaryEditorCanvas` 承载可编辑画布、缩放工具栏和笔势事件。
- 新增工作区组合层统一管理基础稿、编辑覆盖层、模式切换和 01–04 重置确认。
- `EditorPage` 继续作为作品名称、状态、保存、自动保存和错误提示的唯一页面协调者。

中央工作区继续使用“输入 / 去底”和“黑白稿编辑”两种模式，不新增独立结果页。

### 决策 13：保存和失败处理复用现有保存状态

`binaryState` 与 `imageState` 一起通过 `createWork`/`updateWork` 保存：

- 笔画结束、撤销、重做、阴阳刻、镜像、边框和线宽变化标记编辑为脏状态。
- 高频设置变化继续使用现有延迟自动保存。
- 点击“草稿”或“保存（已完成）”立即把当前状态写入 localStorage。
- 写入失败时保留内存覆盖层和当前画布，显示失败状态，用户可再次保存。

### 决策 14：A4 导出占位不提前实现 P4

P2 顶部增加“A4 导出”按钮，但 Change 3 中点击只显示“A4 导出将在后续 Change 提供”的页面内提示，不改变路由、不生成 PDF。只有 Change 4/5 完成后才接入真实入口。

不增加“作品列表”可导航入口；P3 导航由 Change 4 负责。

### 决策 15：纯函数处理与 Canvas 事件分离

覆盖层绘制、压缩、解码、阴阳刻、镜像、边框和纯黑白守卫实现为纯函数或可注入 Canvas context 的模块。组件只负责指针坐标、视图缩放和状态编排。测试使用固定像素样本与 Canvas mock，不依赖真实浏览器绘制。

## Risks / Trade-offs

- 覆盖层与基础稿参数不一致会污染结果 → 使用生成签名校验，不一致时丢弃覆盖层并提示。
- 20 份覆盖层快照会占用内存 → 使用 2 bit/像素压缩快照，并在每次撤销/重做后释放不再使用的快照。
- 01–04 参数变化会丢失手动修整 → 使用明确确认提示，确认后才重置。
- 阴刻和镜像下编辑坐标容易反向 → 将逆变换集中在一个事件映射函数，并用四种模式组合测试。
- 边框可能遮挡边缘笔迹 → 边框按固定顺序最后合成，不修改覆盖层；用户可切换为无边框继续检查。
- localStorage 容量有限 → 覆盖层压缩、限制画布 512×512、不保存历史，并沿用容量失败提示。
- jsdom 不实现真实 Canvas → 核心像素逻辑用纯函数测试，交互使用 Canvas mock；真实浏览器视觉仍需人工验收。

## Migration Plan

1. 增加 `binaryState` 类型、默认值、校验器和黑白编辑状态序列化函数。
2. 将 `APP_STORAGE_VERSION` 从 2 升级到 3。
3. 实现 v1→v3、v2→v3 迁移；所有旧作品补默认 `binaryState`。
4. 读取 v3 时校验覆盖层尺寸、Base64 结构和设置枚举；损坏覆盖层安全降级为空修整层并提示。
5. 写入失败时不清理旧 v2/v3 数据，保留内存状态供用户重试。
6. 若后续版本需要回滚，仅回退应用代码；v3 数据不得被旧版本静默覆盖，旧版本应按现有“不兼容版本”策略安全回退。

## Test Strategy

- 像素纯函数：画笔、橡皮、线宽、连续线段、覆盖层应用、压缩往返、阴刻、镜像、边框和纯黑白守卫。
- 组件：05/06 控件、禁用态、撤销重做、缩放、确认提示、A4 占位提示和可访问标签。
- 数据：v1/v2→v3 迁移、v3 守卫、覆盖层签名校验、损坏数据降级和容量失败。
- 集成：固定样本上传 → 去底 → 手动修整 → 阴刻/镜像/边框 → 自动保存 → 重新打开恢复。
- 范围回归：P2 不出现 P3/P4/PDF 功能，不调用 API、外部 AI 或服务端。
- 最终门禁：`npm test`、`npm run typecheck`、`npm run build`、OpenSpec 严格校验。
