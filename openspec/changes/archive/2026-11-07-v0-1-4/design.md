# 设计（Design）

## Context

Change 1–3 已提供 localStorage v3 作品、P1 登录、P2 编辑和纯黑白最终渲染。当前路由只有登录和编辑页，作品服务缺少列表删除操作，P2 也没有进入作品列表的入口。

本设计依据 `proposal.md` 和 `specs/work-list-preview/spec.md`，复用现有作品数据与黑白处理函数。

## Goals / Non-Goals

**目标：**

- 增加受保护 P3 路由、作品筛选、卡片、预览弹窗和管理操作。
- 复用已保存作品即时重建黑白与红印预览，不保存派生图。
- 提供可验证的已完成作品全选、数量显示和永久删除。

**非目标：**

- 不实现 P4 排版、PDF、导出记录或分享。
- 不新增作品字段、localStorage 版本或后端 API。
- 不验证真实打印、转印或雕刻。

## Decisions

### 决策 1：路由使用 `#/works`

`AppRoute` 增加 `works` 类型；`App` 在无活动账号时阻止访问。P4 仍不解析，Change 5 再接 `#/export/a4`。

### 决策 2：P2 增加作品列表入口

P2 顶部增加“作品列表”导航按钮；P3 顶部提供“新建作品”。继续编辑和新建均复用现有 `/editor/new`、`/editor/:workId` 路由。

### 决策 3：列表读取当前账号数据

P3 使用 `listActiveUserWorks()`，筛选和选择仅在内存中进行。切换筛选时清空选择；选择集合不作为持久数据。

### 决策 4：缩略图和预览复用最终渲染管线

新增 `WorkPreviewCanvas`：

- 通过 `prepareSourceDataUrl` 解码保存源图。
- 用 `renderBinaryDraft` 和 `renderFinalBinary` 生成最终黑白像素。
- 黑白预览直接显示；红印预览把黑色像素映射为 `#C62828`，白色保持 `#FFFFFF`。
- 组件只显示结果，不修改作品。

同一组件用于卡片缩略图和弹窗预览，尺寸由调用方控制。

### 决策 5：预览弹窗使用当前保存状态

弹窗通过作品 ID 从当前账号作品列表查找到快照后显示，不额外创建结果页，也不引入预览持久对象。

### 决策 6：已完成筛选中的选择规则

只在“已完成”筛选提供选择控件。“一件全选”选择当前已完成列表全部作品；已选数量显示在全选文字下方。离开已完成筛选或删除后重新计算选择。

### 决策 7：删除采用二次确认和单次原子写入

作品服务增加 `deleteActiveUserWorks(workIds)`：

- 只处理当前账号拥有的 ID。
- 一次读取、过滤、写入 localStorage。
- 返回实际删除数量；无活动账号时返回失败。

P3 使用确认弹窗，取消不调用删除服务。

### 决策 8：A4 导出在 Change 4 只做占位

P3 的 A4 导出按钮在 Change 4 中只提示后续 Change 提供，不解析或跳转 P4。Change 5 再将其接入真实路由。

### 决策 9：无障碍与空状态

筛选按钮使用 `aria-pressed`；选择控件使用 checkbox 语义；预览和删除确认使用带名称的 `role="dialog"`。空筛选显示明确文案。

## Risks / Trade-offs

- 每张卡片重建源图会增加计算 → 限制缩略图显示尺寸，并按作品 ID/保存时间复用 canvas 组件。
- 删除不可恢复 → 必须二次确认，服务只接受当前账号作品。
- localStorage 损坏源图无法预览 → 显示占位和错误说明，不影响列表操作。
- 选择集合可能与筛选变化不一致 → 每次筛选变化清空选择。

## Migration Plan

不修改持久数据结构；直接读取现有 v3 作品。回滚只需移除 P3 路由和 UI，不影响已有作品数据。

## Test Strategy

- 路由：登录保护、`#/works`、仍不开放 P4。
- 服务：当前账号列表、批量删除、跨账号隔离、写入失败。
- 组件：筛选、卡片、空状态、预览弹窗、红印映射、全选、数量、删除确认。
- 集成：P2 → P3 → 预览 → 继续编辑 → 已完成全选 → 删除 → 刷新恢复。
- 最终门禁：测试、类型检查、构建、OpenSpec 严格校验。
