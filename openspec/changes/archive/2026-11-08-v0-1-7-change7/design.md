# 设计（Design）

## Context

Change 7 已完成多轮 P2/P3 交互优化，但尚未归档交付。前几轮已经建立固定 P2、双模式、多背景规则、边框粗细、空作品保护和版本化本地存储；本轮在不拆出新 Change 的前提下继续调整同一交付版本。

第四轮聚焦图片编辑状态链：图片橡皮每抬笔会替换源图并强制回到取色工具，裁剪也会触发源图刷新，造成背景规则丢失、黑白稿短暂失效和模式切换受限；同时效果外边距仍使用百分比且存在隐性基础留白，边框也缺少独立的物理外边距。

产品行为见 `proposal.md` 和 `specs/`，本文记录实现方式与取舍。

## Goals / Non-Goals

**目标：**

- 为 P1–P4 提供统一、精致、可缩放的内嵌 SVG 品牌头部。
- 把 P2 模式入口移入左侧工具区，将右侧画布扩大到填满剩余空间，并以 1:1 为默认显示基准。
- 用按需弹窗替代常驻状态和免责声明，覆盖保存成功、未保存离开、重新上传替换三种关键时刻。
- 用图标替代工具数字序号，统一工具模块标题结构。
- 增加轮廓线粗细和边框外边距，移除新建粗线边框，并完成 v7 数据迁移。
- 允许 P2 当前有效作品先自动保存为已完成，再直接进入 P4。

**非目标：**

- 不新增服务端、API、数据库或外部 AI。
- 不改变 P3 筛选、删除确认、P4 排版和 PDF 1:1 输出规则。
- 不恢复新手绘、新建残破边或新建粗线入口。
- 不拦截浏览器标签页关闭；未保存拦截仅覆盖应用内导航和替换作品。
- 不验证真实打印、转印和雕刻效果。

## Decisions

### 决策 1：新增共享 `BrandHeader`

建立单一的 `BrandHeader` 组件，由 P1–P4 共同使用：

- 左侧为内嵌 SVG 印章图形 + 放大的 `CUNSTONE` 字标。
- 右侧用竖分隔线连接页面名称。
- 页面名称映射为“登录 / 注册”“创作编辑”“作品列表”“A4 导出”。
- 删除现有页面中的 `CUNSTONE · P1/P2/P3/P4` eyebrow 文字。

Logo 采用“方形印面 + 负形刻痕 + 几何留白”的原创几何标识：外轮廓是略带不对称呼吸感的圆角方印，内部以一条负形曲线和两处刻痕形成类似 “C” 的印记；不使用渐变、阴影或位图，以保证高分辨率清晰和高级感。Logo 提供 `role="img"` 与可读名称。

考虑过使用 AI 生成位图 Logo，但它难以保证小尺寸清晰、可维护和不同背景适配。最终选择代码内嵌 SVG；如后续需要更复杂的品牌探索，再单独生成概念稿。

### 决策 2：P2 采用品牌头部 + 固定操作区 + 全高编辑器

P2 桌面布局改为：

1. 页面顶部显示共享品牌头部。
2. 下方是固定高度的作品操作区，作品名称标签和输入框同一行，右侧依次为作品列表、草稿、保存、A4 导出、清除。
3. 剩余高度全部交给编辑器工作区。

编辑器左侧工具列固定约 280–300 px，右侧使用 `minmax(0, 1fr)` 占满全部剩余宽高。页面本身不滚动，只允许左侧工具列表滚动和画布内部查看区域滚动。

### 决策 3：画布默认 1:1，不拉伸

默认新作品为 25×25 mm 正方形，因此画布默认按照 1:1 宽高比展示。画布容器使用 `aspect-ratio` 或等价等比约束，在可用区域内最大化居中显示：

- 正方形：始终 1:1。
- 长方形：按实际宽高比展示，不强制拉成 1:1。
- 圆形：使用 1:1 外接方形边界。

“1:1 显示”指画布自身的宽高比例和像素等比，不是把 100% 缩放误写成物理尺寸；实际毫米尺寸仍由作品尺寸驱动。

### 决策 4：模式入口移入左侧并改名为“图片编辑/黑白稿编辑”

左侧工具区顶部放置模式切换。默认“图片编辑”，只显示上传和背景去除；切换“黑白稿编辑”后显示外形尺寸、效果适配、黑白稿编辑、阴/阳刻与边框。两种模式始终可双向切换，模式切换本身不清空任何作品状态；没有图片时黑白稿画布显示空状态。

右侧不再保留模式切换栏，把高度全部用于画布和必要的画布提示。

### 决策 5：六个模块统一为图标 + 名称

新增 `ToolModuleHeading`，使用统一尺寸的内嵌 SVG 图标替代 01–06：

- 上传图片：图片/上传箭头。
- 纯色背景去除：透明棋盘与取样滴管。
- 外形与尺寸：比例框与尺寸线。
- 效果与适配：滑杆与轮廓节点。
- 黑白稿编辑：画笔。
- 阴/阳刻与边框：方印轮廓与阴阳半圆。

图标为装饰，旁边的模块名称继续作为可访问标题；不把数字藏进 `aria-label`，避免界面视觉与读屏语义不一致。

### 决策 6：常驻状态改为事件弹窗

删除常驻“草稿”“未保存”状态标签与本地账号免责声明。保存成功后使用统一 `EditorNoticeDialog`：

- 草稿成功：标题“草稿已保存”，提示本地浏览器保存范围及账号只用于区分作品。
- 已完成成功：标题“作品已保存”，说明可继续编辑、预览或进入 A4，并提示账号安全边界。

失败仍显示错误提示，不弹成功弹窗。保存中的短暂状态可以使用按钮禁用或非侵入状态，但不恢复常驻“未保存”文字。

### 决策 7：未保存离开与替换使用显式动作队列

把导航和上传动作抽象成待执行动作：

- `pendingNavigation`：作品列表、切换账号等应用内离开。
- `pendingUpload`：上传入口或画布中心上传。

未保存离开弹窗：

- 标题：`当前修改尚未保存`
- 正文：`离开后，本次未保存的修改会丢失。`
- 动作：`继续编辑`、`保存草稿并继续`、`直接离开`

替换作品弹窗：

- 标题：`替换当前作品？`
- 正文：`当前画布已有内容，替换后会使用新图片重新开始。`
- 动作：`取消`、`保存草稿并替换`、`直接替换`

选择保存动作时先写入草稿；写入成功后才执行原动作。写入失败则清空待执行动作并保留页面内容。替换弹窗触发条件为“当前画布已有图片或可打印内容”，不只看 dirty 标记，因为自动保存后的进行中作品仍可能被误覆盖。

浏览器标签页关闭和刷新无法稳定展示自定义弹窗，不纳入本轮拦截范围。

### 决策 8：P2 直接 A4 导出复用统一保存函数

把保存逻辑重构为可返回结果的 `persistWork(status)`：

1. 校验名称。
2. 校验可打印内容。
3. 新建或更新作品。
4. 返回保存后的 `WorkRecord`。

普通“草稿”和“保存”按钮在结果成功后显示弹窗。A4 导出使用同一个函数保存为 `completed`，不显示保存成功弹窗，直接把返回作品 ID 写入导出会话并导航到 P4。若保存失败或作品为空，则停留在 P2。

这样可以避免另写一套重复校验，也保证 P2 导出和普通保存的存储口径一致。

### 决策 9：轮廓粗细使用 1–8 级边界膨胀

`WorkImageState` 新增 `outlineThickness: number`，默认 1，范围 1–8。仅当效果为轮廓线稿时显示滑杆。

实现上先生成 1 像素基础轮廓，再按级别做有限次边界膨胀，形成 1–8 级黑线；结果继续合成为纯黑纯白。轮廓粗细加入生成签名，因此调整时沿用已有“清除手动修整确认”流程。

### 决策 10：新建边框只保留无、单线、双线

新边框选项移除粗线，保留无、单线、双线。边框粗细滑杆继续控制单线和双线宽度。

v1–v4 中的历史粗线必须迁移为单线：旧 v1–v3 粗线转换为单线并设置等效默认粗细；v4 已有 `borderThickness` 时把单线宽度设置为约两倍的旧值并限制在 1–8。这样无需保留“历史粗线”独立按钮，也不会丢失旧作品边框。

历史残破边仍按只读兼容状态处理。

### 决策 11：历史轮次 localStorage 升级为 v5

当前代码已在开发中使用 v4。由于本轮新增 `outlineThickness`、移除新建粗线并调整轮廓算法，本地存储升级为 v5：

- v1/v2：先补齐图片与黑白默认状态。
- v3：单背景转规则，轮廓粗细补 1。
- v4：轮廓粗细补 1，粗线转等效单线。
- 所有旧手动覆盖层在迁移后重算 `generationSignature`，保持覆盖层数据。
- `processingVersion` 升为 3。

### 决策 12：作品名称改为同行表单

作品名称区域使用水平 label/input 布局，桌面下标签固定宽度、输入框弹性占满；操作按钮在右侧单独成组。小屏可换行，但标签与输入仍保持视觉关联。

### 决策 13：精简背景工具文案

删除“上传图片后可为每条颜色规则取样”。保留唯一必要说明“点击背景区域指定要移除的颜色”。“添加背景颜色”统一改为“添加待选颜色”。

### 决策 14：验证覆盖品牌、模态和跨页面数据

- 品牌：四页页面名称、Logo SVG、无 P 编号角标。
- P2：模式位置、画布 1:1、工具图标、名称同行、保存成功弹窗、未保存离开与替换弹窗。
- 图像：轮廓 1/8 级像素差异、签名变化、保存恢复。
- 边框：新选项无粗线、历史粗线迁移、残破边兼容。
- 导出：草稿/新作品自动保存为已完成并进入 P4；空作品/失败停留。
- 数据：v1–v6 → v7 迁移及覆盖层签名重算。

### 决策 15：图片编辑采用显式画布工具

图片编辑增加 `取色 / 裁剪 / 透视裁剪 / 橡皮` 四种互斥画布工具。选择背景颜色行时自动回到取色；裁剪拖拽矩形；透视裁剪依次点击左上、右上、右下、左下；橡皮按笔画连续擦除。裁剪和透视在点击“应用”后更新工作图，橡皮抬笔后继续保持橡皮工具。

工作图更新保留全部背景颜色规则，不触发源图重新解码或工具重置；如存在手动黑白修整，先沿用现有确认弹窗。图片橡皮大小保存在 `imageEraserSize`，范围 1–80 px，画布显示同尺寸光标圆。

### 决策 16：透视裁剪使用单应性变换

四个点定义源图四边形，系统按对边平均长度确定输出矩形宽高，通过解 8 参数单应性矩阵将输出矩形逐像素反投影到源图。矩形裁剪直接复制选区像素。

### 决策 17：锐化与外边距进入图片处理签名

`sharpenAmount` 为 0–8，默认 1；0 不处理，1–8 进行相应强度的二值边缘增强。`outerMarginMm` 为 0–20 mm、步进 0.1 mm、默认 0；不再保留旧的 10% 隐性内边距，0 mm 时内容最短边贴齐印章边界。两者均加入生成签名。

### 决策 18：手绘画笔与橡皮独立大小

`WorkBinaryEditState` 增加 `eraserSize`，画笔继续使用 `brushSize`。手绘区改名为“手绘”，按当前工具只显示对应大小滑杆。二值编辑画布显示与当前工具大小一致的圆形光标，并显示工具名称和 px 数值。

### 决策 19：草稿与已完成共用选择区

P3 仅在“已完成”和“草稿”筛选显示多选操作区。两者都显示已选数量、一键全选和删除；只有已完成显示 A4 导出。删除继续使用原有二次确认和批量本地写入。

### 决策 20：A4 下载入口顶部化

P4 删除底部拖动/PDF说明，将“下载 PDF”放入顶部排版工具栏右侧，保留原有生成中状态和错误处理。

### 决策 21：localStorage 升级为 v6

该决策记录第三轮 v6 结构。第四轮已将其继续升级为 v7，见决策 24。

### 决策 22：图片编辑使用连续工作图并延后持久化

图片橡皮、矩形裁剪和透视裁剪共同维护当前编辑会话的工作图：

- 橡皮一笔结束后只更新内存工作图，工具保持橡皮，下一笔从上一笔结果继续。
- 裁剪和透视应用后更新工作图，但继续保留背景颜色规则、黑白设置和模式切换能力。
- 图片编辑不再逐笔触发自动保存；用户点击“草稿”“保存”或“A4 导出”时，使用最新工作图生成数据并写入作品。
- 有未保存工作图时仍参与离开/替换确认，避免用户误以为已经持久化。

### 决策 23：模式切换不再依赖黑白基础稿

“图片编辑”和“黑白稿编辑”始终可双向切换。无图片来源时进入黑白稿编辑仍显示完整工具区和空画布说明，但画笔、橡皮、撤销重做等依赖基础稿的操作禁用。

### 决策 24：localStorage 升级为 v7

在 v6 基础上：

- `outerMarginPercent` 替换为 `outerMarginMm`，`processingVersion` 升为 5。
- 黑白状态新增 `borderMarginMm`，`editVersion` 升为 4。
- v6 的百分比外边距按作品短边换算为毫米并保留到 0.1 mm。
- v1–v6 迁移后补齐默认值；存在覆盖层时重算生成签名。

### 决策 25：效果外边距使用物理毫米

效果与适配的外边距按作品实际宽高换算到输出像素：水平方向使用 `outerMarginMm / widthMm`，垂直方向使用 `outerMarginMm / heightMm`。0 mm 时不再人为保留 10% 基础留白，因此内容最短边可以贴齐印章边界。

### 决策 26：边框外边距独立于内容外边距

黑白状态新增 `borderMarginMm`，范围 0–20 mm、步进 0.1 mm、默认 0。边框外边距只移动系统边框距画布外边缘的距离，不改变主体内容外边距；方形和长方形按各自物理宽高换算 inset，圆形按直径换算。该值由 P2、P3、P4 和 PDF 的共享最终渲染器统一使用。

## Risks / Trade-offs

- **多弹窗打断操作** → 只在保存成功、真实未保存离开、已有作品替换三类事件触发，普通模式切换不弹窗。
- **自动保存导致“未保存”判断模糊** → 替换弹窗按“当前画布是否有内容”判断，避免自动保存后的作品被静默覆盖。
- **直接导出改变状态** → 明确将 P2 当前作品保存为已完成，P3 仍只允许已完成作品进入导出。
- **轮廓膨胀影响性能** → 轮廓图基于 512 最大工作稿，1–8 次有限膨胀，并缓存基础轮廓。
- **v7 迁移复杂** → 保留 v1–v6 固定原始夹具，逐版本断言规则、轮廓、mm 外边距、工具默认值和覆盖层签名。
- **Logo 不够“高级”** → 使用简洁几何比例、细节刻痕和统一字距，不使用花哨渐变；实现后做多尺寸截图检查。
- **品牌头部改动 P1/P4** → 仅替换头部，不改变登录、排版和 PDF 业务逻辑。

## Migration Plan

1. 保留 v3/v4/v5/v6 固定 localStorage 夹具，覆盖轮廓、粗线、残破边、手绘和手动覆盖层。
2. 引入 v7 类型、校验和迁移，读取时先形成内存 v7。
3. 用户下一次有效保存时写回 v7；空白作品仍不触发覆盖。
4. 验证四页品牌头部和 P2/P3/P4 数据链路。
5. 问题修复不覆盖已占用版本，按项目规则进入下一个 PATCH。

## Test Strategy

- 单元测试：轮廓 1/8 级、生成签名、粗线换算、v1–v6 迁移。
- 单元测试：裁剪、透视单应性、连续图片橡皮、锐化 0/8、mm 外边距 0/20、边框 mm 间距。
- 组件测试：品牌头部、图标标题、名称同行、保存成功弹窗、未保存离开、替换作品弹窗、直接导出。
- 组件测试：画布工具显隐、连续橡皮、保留背景规则、随时切换模式、四点选择、橡皮光标、手绘双滑杆、草稿多选删除、P4 顶部下载。
- 集成测试：P2 草稿/新作品直接 A4、保存失败停留、P4 数据正确。
- 真实浏览器：1440×900 检查 P2 全高布局、1:1 画布、左侧滚动和所有弹窗。
- 最终门禁：测试、类型检查、构建和 OpenSpec 严格校验。
